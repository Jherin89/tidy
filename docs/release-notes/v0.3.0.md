**tidy 0.3** ages files by Date Added (so a copied old installer is not trashed on the first run), treats iWork packages as one item, and actually stores `watch --install` flags in the launchd agent.

### Highlights

- **Age by Date Added.** `older_than` (the `--older-than` flag and the rule condition) uses Finder's Date Added on macOS. When that stamp is missing, and on Linux, the age is the later of created (birth) and modified. `tidy explain` prints the source, for example `5d 3h old (created), needs ≥ 30d`. JSON includes `age_source`.
- **Package documents.** A directory whose extension is listed on a matching rule (`.pages`, `.numbers`, `.key`, `.rtfd`, …) is moved or trashed as a whole. Other directories are still skipped. `.app` is only a package if a rule lists it. Duplicate detection skips packages. Undo restores the whole tree.
- **`tidy watch --install` keeps `--rules` and `--older-than`.** They are written into `ProgramArguments` (`--rules` as an absolute path). `--apply` and `--json` with `--install` are rejected. `tidy watch --status` shows the configured arguments.
- **`scripts/mac-smoke-test.sh`** is an isolated Mac check (temp folder, distinct launchd label, never `~/Downloads`).

### Install

Homebrew (tap formula rendered by `scripts/bump-homebrew.sh`):

```bash
brew install jherin89/tap/tidy
```

Or a release archive from this page:

| Platform | Archive |
| --- | --- |
| macOS, Apple Silicon and Intel | `tidy-0.3.0-universal-apple-darwin.tar.gz` |
| Linux x86_64 (static musl) | `tidy-0.3.0-x86_64-unknown-linux-musl.tar.gz` |
| Linux aarch64 (static musl) | `tidy-0.3.0-aarch64-unknown-linux-musl.tar.gz` |

Each `.tar.gz` has a matching `.sha256` (`shasum -a 256` layout). The binary is not notarized. On a Mac, clear quarantine after unpacking:

```bash
xattr -d com.apple.quarantine tidy-0.3.0-universal-apple-darwin/tidy
```

Or build from source: `cargo install --git https://github.com/Jherin89/tidy --tag v0.3.0`

### Known limitations

- The binary is not notarized.
- On macOS, `tidy undo` still cannot pull files back out of the Trash. It names each file and its original location so you can use Finder's **Put Back**. Moved files come back on their own. The default Trash method is Finder so Put Back is offered. `TIDY_TRASH_METHOD=nsfilemanager` is the headless alternative and may not offer Put Back.
- `tidy watch --install` / `--status` and the real-Trash path were checked with a fake `launchctl` and with the macOS CI job. Run `scripts/mac-smoke-test.sh` on a real Mac to confirm the agent, Date Added, packages, and Finder Put Back together.
- The real-Trash test runs in CI with `TIDY_TRASH_METHOD=nsfilemanager`, so the default Finder method was not exercised there.
