**tidy 0.2** explains a single file, sends extra copies to the Trash, and can install a macOS launchd agent. Release binaries now cover Apple Silicon, Intel Macs, and Linux.

### Highlights

- **`tidy explain FILE`** walks the active rules and shows which condition passed or failed. The winner is the same rule the plan would pick, including a collision suffix such as `notes (1).txt`.
- **Duplicate copies.** A new `duplicate` condition matches extra byte-identical files. The built-in **Duplicates** rule is first and trashes them (Trash + undo, the same as any other trash rule). The oldest copy is kept and falls through to the other rules. Zero-byte files are never duplicates.
- **`tidy watch --install`** writes and loads a LaunchAgent. `--status`, `--uninstall`, and `--install --print` go with it. `--print` is safe to run anywhere; it only writes the plist XML to stdout.
- **Clearer privacy errors** when macOS blocks Downloads (`Operation not permitted`).
- Flags belong to the command that uses them. `tidy init --help` no longer lists `--apply`.

### Install

Homebrew (tap formula rendered by `scripts/bump-homebrew.sh`):

```bash
brew install jherin89/tap/tidy
```

Or a release archive from this page:

| Platform | Archive |
| --- | --- |
| macOS, Apple Silicon and Intel | `tidy-0.2.0-universal-apple-darwin.tar.gz` |
| Linux x86_64 (static musl) | `tidy-0.2.0-x86_64-unknown-linux-musl.tar.gz` |
| Linux aarch64 (static musl) | `tidy-0.2.0-aarch64-unknown-linux-musl.tar.gz` |

Each `.tar.gz` has a matching `.sha256` (`shasum -a 256` layout). The binary is not notarized. On a Mac, clear quarantine after unpacking:

```bash
xattr -d com.apple.quarantine tidy-0.2.0-universal-apple-darwin/tidy
```

Or build from source: `cargo install --git https://github.com/Jherin89/tidy --tag v0.2.0`

### Known limitations

- The binary is not notarized.
- On macOS, `tidy undo` still cannot pull files back out of the Trash. It names each file and its original location so you can use Finder's **Put Back**. Moved files come back on their own. The default Trash method is Finder so Put Back is offered. `TIDY_TRASH_METHOD=nsfilemanager` is the headless alternative and may not offer Put Back.
- `tidy watch --install` / `--status` and the real-Trash path were checked with a fake `launchctl` and with the macOS CI job. Confirm both once on a real Mac before relying on the agent.
- The real-Trash test runs in CI with `TIDY_TRASH_METHOD=nsfilemanager`, so the default Finder method was not exercised there.
